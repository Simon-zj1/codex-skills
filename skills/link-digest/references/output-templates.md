# 输出模板与可视化选择

## 模板 A：单条推文 / 短内容（默认半屏）

```markdown
**一句话**：<这条推的核心主张>

- 作者 / 出处：<@handle、时间>
- 关键数据：<互动量、数字、模型名，若有>
- 依据：<作者给了什么理由或证据，没有就说"仅为主张">
- 值得注意：<反直觉点、争议点、或与常识冲突处>

**文中提到的链接**：<逐条一句话说明它是什么、值不值得跟>
```

## 模板 B：长文 / 论文 / 官方文档

```markdown
## 一句话结论
<不超过两行>

## 核心要点
| 要点 | 内容 | 证据/数据 |
| --- | --- | --- |
| ... | ... | ... |

## 技术细节
<原理、实现、参数、接口、版本号；用列表或小表格，不要流水账>

## 局限与反方视角
<作者承认的限制 + 你判断的薄弱处>

## 文中引用链接分析
| 链接 | 是什么 | 与主题关系 | 结论 |
| --- | --- | --- | --- |
| ... | ... | ... | 值得看 / 可略过 / 未抓到 |

## 对用户的意义
<能立刻用的结论、可复现的步骤、需要进一步验证的点>
```

## 模板 C：多链接综合（用户一次给多个，或主链接带大量外链）

在模板 B 基础上：

- 开头加一张**对比表**：每条链接一行（来源、核心主张、可信度、与主题关系）。
- 结尾加**关系图**（谁引用谁、谁反驳谁），用缩进列表或 ASCII 小图。
- 观点冲突时单列「分歧」一节，写清各自依据，不要强行调和。

## 可视化选择

| 场景 | 形式 |
| --- | --- |
| 多项对比、映射、字段清单 | Markdown 表格 |
| 步骤、流水线、请求链 | 有序列表 + 缩进，或 ASCII 流程图 |
| 层级、依赖、引用关系 | 缩进树 / ASCII 图 |
| 数据趋势、分布、需要交互探索 | `visualize` skill（生成交互式可视化） |
| 原文里的图表/截图是关键证据 | 用 `view_image` 看图后在总结中描述其含义 |

原则：可视化是为了让关系一眼看懂。一两句话能说清的事不要画图；画图时不要为了好看而牺牲准确性。

## 长度校准

| 输入 | 输出 |
| --- | --- |
| 单条推文、短贴 | 半屏，5–8 行 |
| 一篇博客 / 文档页 | 一屏，带 1–2 张表 |
| 论文、长报告、多链接 | 完整结构，允许更长，但每节只留必要信息 |

## 示例（单条推文，示意）

> **一句话**：作者主张 AI 从业者私下普遍相信"本十年内 AI 可能灭绝人类"，并认为公开表态被刻意说得缓和。
>
> - 作者 / 出处：@hilbertspaess，2026-09-09，13.2 万点赞 / 2665 万阅读
> - 依据：作者称自己在私下听到同样的恐惧，但公开场合人们会用更"稳妥"的措辞；**未给出可核验证据**
> - 值得注意：这是**立场性断言而非事实陈述**，属于"圈内人转述"，可信度取决于作者身份与可验证性
> - 文中无外链

注意最后一条：没有证据就写"未给出可核验证据"，不要替作者补理由，也不要假装它是研究结论。
