# 论文阅读工作流

## 0. 输入归一化

支持以下输入：

- arXiv URL 或 ID；
- DOI；
- 出版社、OpenReview、项目主页链接；
- 本地 PDF；
- 论文题目；
- 一组论文或一个方向关键词。

先记录：

- 标题、作者、年份、发表 venue；
- 版本和访问日期；
- 官方代码、数据、项目页；
- 论文类型：方法、系统、基准、综述、立场、实证分析；
- 研究领域：Agent、机器人、具身智能、跨领域。

若同一论文有多个版本，优先使用最新正式版；若用户明确要求，按指定版本阅读。

## 1. 解析与结构恢复

目标是得到可追溯的阅读底稿：

1. 抽取正文、章节标题、摘要、附录和参考文献。
2. 保留页码边界。
3. 抽取图、表、公式、算法框及其原始标题。
4. 表格转成结构化格式，公式保留 LaTeX。
5. 记录解析失败区域，例如跨页表格、扫描页、复杂公式。

推荐策略：

- 清晰电子版 PDF：原生文本抽取；
- 双栏、公式多、表格复杂：MinerU 或 Docling；
- 扫描版：OCR；
- 本地大批量论文问答：PaperQA2。

### 解析门

- 摘要、方法、实验和结论章节完整；
- 主要图表的标题和正文引用能对应；
- 随机抽查 3 个数字能回到原页；
- 明显缺页、乱码或公式错位已标记。

未通过解析门时，不直接进入高置信度总结。

## 2. 证据抽取

每条证据记录至少包含：

```json
{
  "claim": "论文提出的核心结论",
  "evidence_type": "result",
  "location": "p.6, Table 2",
  "quote_or_paraphrase": "能核验原文的短引文或严格转述",
  "value": "数值、比较或定性结果",
  "confidence": "high",
  "notes": "基线、条件或限制"
}
```

证据类型：

- `problem`
- `assumption`
- `method`
- `implementation`
- `dataset`
- `metric`
- `result`
- `ablation`
- `limitation`
- `reproduction`
- `claim`

规则：

- 图表结论也必须记录图表编号。
- 作者的主张标记为 `paper_claim`，独立评估标记为 `our_assessment`。
- 有冲突的数据必须并列，不强行合并。
- 无法定位的二手信息不得写成事实。

## 3. 单篇结构理解

按以下顺序重建论文：

1. **问题**：要解决什么，为什么现在重要。
2. **缺口**：已有方法具体缺什么，而不是泛泛说“效果不好”。
3. **核心假设**：论文成立依赖哪些前提。
4. **一句话思想**：去掉术语后如何通俗解释。
5. **方法链**：输入 -> 表示 -> 模型/策略 -> 训练 -> 推理 -> 输出。
6. **关键设计选择**：每个模块解决什么问题，移除后会怎样。
7. **数据与实验**：环境、任务、数据量、硬件、训练预算、评测协议。
8. **结果**：主结果、消融、泛化、真机或开放环境结果。
9. **失败与边界**：失败案例、负结果、适用条件、安全风险。
10. **贡献与价值**：真正新增的是什么，哪些只是工程组合。

### 理解门

必须能用三句话回答：

- 这篇论文到底改了什么？
- 证据是否足以支持作者结论？
- 对机器人或 Agent 研究者的实际价值是什么？

## 4. 机器人 / Agent 专属理解

使用 [agent-robotics-taxonomy.md](agent-robotics-taxonomy.md)。特别检查：

- Agent：环境、状态、动作、观察、规划、记忆、工具、训练、评测、长程能力。
- 机器人：本体、传感器、动作空间、控制频率、数据来源、仿真、真机、安全、恢复。

不要只关注模型名称。优先判断系统和评测协议是否真的支持论文声称的能力。

## 5. 批判性复核

至少回答以下问题：

1. 最强基线是否是当前合理基线？
2. 数据规模是否足以区分方法收益和训练量收益？
3. 评测是否覆盖长尾、长程、分布外和失败恢复？
4. 消融是否验证了核心机制，还是只验证了整体设置？
5. 结果是否有置信区间、重复实验或多种子？
6. 仿真结论是否能映射到真机或真实用户？
7. 成本、延迟、内存、样本效率和安全性是否被报告？
8. 代码、数据、提示词和超参数是否足够复现？
9. 是否遗漏与论文结论相反的证据？
10. 结论是否超出实验范围？

输出采用：

- `强证据`
- `中等证据`
- `弱证据`
- `未验证`

## 6. 单篇输出

默认深读包：

- `00_one_page.md`
- `01_deep_note.md`
- `evidence.jsonl`
- `mindmap.mmd`
- `deck_storyboard.md`

可选输出：

- 复用清单：代码、数据、提示词、模型、环境和成本。
- 复现计划：任务拆解、环境要求、关键实验、失败检查点。
- 方法迁移卡：可迁移机制、不可迁移部分、适配假设。
- 一页图：研究问题、方法、结果、边界。

## 7. 多篇综合

多篇任务至少输出：

- `multi_paper_matrix.md`：问题、方法、数据、评测、结果、局限；
- `synthesis.md`：共识、分歧、方法演化、证据强弱；
- `research_gaps.md`：可验证的研究空白和最低成本验证实验；
- `reading_order.md`：先读什么、为什么、每篇要回答什么。

横向矩阵的比较维度由研究问题驱动，不要机械比较所有字段。

## 8. 可视化与交付

不同输出不是同一内容的换皮：

- 一页卡：先讲价值和结论；
- 深读笔记：讲清机制、证据和边界；
- PPT：按论证节奏组织，每页只承担一个论点；
- 图文 PDF：适合完整解释机制和实验；
- 思维导图：适合展示概念关系、方法树和阅读路径；
- 海报：适合一项研究或一组方法的总览。

图表选择：

- 机制：流程、框图、公式切片；
- 对比：矩阵、条形图、雷达图；
- 演化：时间线、方法树；
- 评测：任务-指标-结果矩阵；
- 关系：知识图谱或思维导图。

若复用论文图片，必须标注来源页码、原图号，并避免改变原图含义。若重绘，必须说明“根据原图重绘”。

## 9. 交付前质量门槛

### 内容

- 事实性主张有定位；
- 核心数字通过回查；
- 作者主张与本项目判断分开；
- 不夸大泛化能力和安全性；
- 至少包含失败案例或适用边界。

### 视觉

- 每张图紧邻对应解释，不做装饰；
- 页面无文字溢出、重叠和低分辨率问题；
- 颜色、字号和层级一致；
- PDF/PPT 逐页渲染检查；
- 图表和引用可追溯到原论文。

### 交付

- 文件命名清晰；
- 源文件与导出文件同时保留；
- `evidence.jsonl` 可被后续追问复用；
- README 或索引记录了版本、日期和来源。

## 10. 阅读后沉淀

每读完一篇，至少更新：

- `papers/library/<paper_id>/meta.json`
- `papers/library/<paper_id>/evidence.jsonl`
- `outputs/<paper_id>/`

若正在维护方向综述，再更新：

- 方法分类；
- 基准和数据集索引；
- 争议与未解决问题；
- 后续阅读顺序；
- 自己的 idea 与可验证实验。
